The 0.2.0 settings page works but looks wrong in three ways: the text is the blocky vanilla Minecraft font, the whole page changes size with the game's GUI scale, and everything is squeezed together. 0.3.0 makes it look like the Shard Launcher: smooth, calm, generous spacing, identical at every GUI scale.

## Part 1: Smooth text everywhere in Shard's UI
- Bundle Inter (the launcher's font; OFL-1.1, from the official rsms/inter release, include the licence file) as Minecraft TTF font providers: `assets/shard/font/ui.json` and `ui-medium.json` / `ui-semibold.json` with `{"type":"ttf","file":"shard:inter-regular.ttf","size":…,"oversample":…}` providers, each followed by a `{"type":"reference","id":"minecraft:default"}` provider so symbols Inter lacks (❤, 🛡, arrows) fall back to vanilla instead of boxes. Expose them through a small `Fonts` helper that returns styled `Component`s (`Style.withFont(Identifier)`) and width/height helpers; draw with `GuiGraphics.drawString(font, Component, …)` and never with shadows in the settings page.
- Pick `size` and `oversample` so glyphs are rasterised at or above the final on-screen pixel size (see Part 2: the page renders at a fixed density, so one oversample value is enough; verify by zooming into screenshots, the edges must be smooth, not stair-stepped). Vanilla's `font.lineHeight` stays 9; use your own line metrics (ascent, line height) for layout so TTF glyphs never clip.
- Use three weights with intent: semibold for module names and section titles, medium for control labels, regular for descriptions. Numbers in sliders use tabular figures if Inter's feature is reachable, otherwise right-align them.
- Add a "Font: Smooth / Vanilla" option (Settings → Appearance) that the HUD modules also honour, default Smooth, so FPS, Keystrokes, Item Counter etc. match the page. The vanilla font must remain a one-click fallback.

## Part 2: The page looks the same at every GUI scale
- Render the settings page, the HUD editor and the popovers in a design space with a fixed pixel density. Compute `pageScale = DESIGN_PX_PER_UNIT / mc.getWindow().getGuiScale()` (choose `DESIGN_PX_PER_UNIT` so the page looks like GUI scale 2 on a 1080p monitor, and add a user slider "Interface size 75%–150%" that multiplies it). Push that scale on `GuiGraphics.pose()` before drawing, lay out in design units (`width / pageScale` wide), and divide mouse coordinates by `pageScale` for hover, clicks, drags and scrolling. Check with `javap` whether `GuiGraphics.enableScissor` in 1.21.11 transforms by the pose (the `ScissorStack`/`ScreenRectangle` path); if it does not, convert scissor rectangles yourself. Items drawn with `renderItem` and the 16x16 glyphs scale with the pose; make sure icons stay sharp (use glyphs or higher-resolution sprites where items pixelate).
- The smoke test must screenshot the mod grid and an open panel at GUI scale 1, 2, 3 and 4 and "Auto" on the 1280x720 dev window, and the layout must be identical in proportion across all of them (same number of columns, same card size relative to the window). Keep one narrow layout for genuinely small windows (phone-sized aspect or below ~900 px wide), not for large GUI scales.
- Rounded corners must be anti-aliased, not per-row stepped fills. Generate a 9-slice corner texture at runtime (NativeImage, 4x supersampled circle, cached per radius, registered as a DynamicTexture) and draw rounded rectangles and outlines with `GuiGraphics.blit` of corners, edges and centre; keep the old fill-based path as a fallback behind a flag. Switch knobs, slider knobs, swatches and the colour picker's markers use the same smooth shapes.
- HUD: add a global "HUD scale" in Settings that normalises HUD elements against the GUI scale the same way, so the HUD also looks the same at every GUI scale; keep per-element scale in the HUD editor on top of it. Positions stay stored as fractions.

## Part 3: Room to breathe
- Redo the spacing with a scale of 4/8/12/16/24 design units: page padding 24, sidebar 176 wide with 12 between rows and a real header block (logo, name, version), card grid gap 16, cards about 72 tall with the icon in a 40-unit tinted square, a two-line description that is actually readable, the switch vertically centred with 16 of clearance. Minimum card width around 220 so the grid shows 3–4 columns on a 1080p-equivalent width, never 5 crammed ones.
- Settings panel: 360 wide, 20 padding, a header with icon, name, one-paragraph description (wrap, do not truncate), then the module controls, then grouped settings with section titles that have 24 above and 8 below, rows 32 tall, 12 between a label and its description, controls right-aligned with a consistent 160-unit control column. Sliders get a numeric field you can click into and type; dropdowns open a popover with 12 of padding and a highlighted current value; colour rows show hex, swatch and an "Edit" affordance.
- Typography hierarchy: page title 18, section title 14 semibold, labels 13 medium, descriptions 12 regular in the muted colour, counts and hints 11. Only one accent colour; it appears on the active switch, focused control, selected category and the primary button, nothing else.
- Motion: 150–200 ms eased transitions for hover, switch knobs, panel slide and popover fade, with a "Reduce motion" toggle that snaps everything.

## Part 4: Detailed, custom settings
- Every HUD module gets: text colour, background colour and opacity, corner radius, padding, text shadow on/off, alignment (left/centre/right where it makes sense), label text (for example "FPS" can become "fps" or be hidden), value colour, and a style preset (Minimal, Card, Outlined). Put shared ones in a `HudStyle` settings group every HUD module declares so the panel shows them in the same order everywhere, plus a global default in Settings → HUD that modules inherit unless overridden.
- Visual and combat modules get the options that are still missing: Crosshair dynamic gap on attack and hit marker; Nametags scale, background opacity and hide-own; Hit Color flash duration; Low Fire preview while editing; Crystal Optimizer highlight colour; Totem Pop Tweaks message format with placeholders (`{name}`, `{count}`); Explosion Optimizer per-particle-type list; Zoom scroll-to-adjust and cinematic camera toggle; Keystrokes key labels, key size, gap and a WASD/Arrows layout choice; Item Counter custom item list editable from the panel.
- Every setting gets a one-line description and, where it matters, a second "details" line shown on hover or in an expandable row; every module gets a longer "About" paragraph in the panel header that says exactly what it does and does not do (for the prediction modules, state that the server stays authoritative).
- Settings page: Appearance (accent colour override with the launcher's as default, interface size, font, blur strength, reduce motion), HUD defaults, Keybinds (one list of every module keybind with capture buttons and conflict warnings), Profiles with an optional description, Server rules with an editor for wildcard patterns, Export/Import (copy config JSON to the clipboard and paste it back), and Reset all with a confirmation.
- Bump the config version to 3 with a migration for every renamed key; existing 0.2.0 configs must load with their values intact. Add tests for the migration and for the layout/scale maths (page scale from GUI scale, mouse mapping, grid column counts).
